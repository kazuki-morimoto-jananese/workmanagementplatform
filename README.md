## すぐ使う

Node.js 24以上が必要です。以下のパスは実際に保存したフォルダーへ置き換えてください。

```powershell
cd C:\work\workmanagementplatform
npm.cmd start
```

ブラウザーで **http://localhost:3000** を開きます。初回に表示されるフォームで、ワークスペース名・管理者名・メールアドレス・12文字以上のパスワードを登録してください。登録したメールアドレスがログインIDになります。既定のID・パスワードはありません。

「サンプルプロジェクトを追加」を選ぶと、操作を試せる4つのプロジェクトと14件のタスクが入ります。実業務だけで始める場合はチェックを外してください。サンプルには利用可能な架空のユーザーアカウントを含みません。

サーバーの停止はターミナルで `Ctrl+C`。次回も同じコマンドで起動できます。`start-worknest.cmd` のダブルクリックでも起動できます。再起動・ブラウザー終了後もデータは保持されます。

別のPCにソースを移した場合は、最初に次を実行します。

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd start
```

PowerShellでは `npm.ps1` が実行ポリシーで拒否される場合があるため、上記では `npm.cmd` を使用しています。

## メンバーを追加する

1. 管理者でログインし、「メンバー」→「メンバーを追加」を選択します。
2. 名前・社内メールアドレス・仮パスワード・権限を指定します。
3. アプリのURL、メールアドレス、仮パスワードを本人に共有します。自動メール送信はありません。
4. メンバーは初回ログイン時に自分のパスワードへ変更します。

既存メンバーの管理者権限は一覧の権限欄から変更できます。自分自身の権限はここでは変更できません。「組織と所属」で会社・事業部・部署・チームを登録し、メンバーの所属を選びます。

公開の会員登録はありません。メンバーの利用を停止すると、その人のログイン済みセッションも失効します。全メンバーが、ワークスペース内の全プロジェクト・タスクを閲覧・編集できます。部署ごとに閲覧範囲を分ける仕様ではありません。

メールドメインを限定する場合は `.env.example` を `.env` にコピーし、`ALLOWED_EMAIL_DOMAIN=yourcompany.co.jp` を設定して再起動します。これは新しいアカウントの作成を制限する設定です。既存アカウントを自動削除したり、メールの所有確認を行ったりする機能ではありません。

## 実装した機能

| 機能               | 内容                                                       |
| ------------------ | ---------------------------------------------------------- |
| ホーム             | プロジェクトの進捗、担当タスク、期限切れ、チームの操作履歴 |
| プロジェクト       | 作成・編集、色、目標期日、進行状況                         |
| タスク             | 作成・編集・削除、担当者、開始日・期日、優先度、タグ、説明 |
| ビュー             | リスト、ドラッグ＆ドロップのカンバン、タイムライン         |
| 依存関係           | 前提タスクの設定、循環の防止、タイムラインの接続線         |
| 検索・絞り込み     | タスク名・説明・タグの検索、担当者・優先度・期日           |
| マルチホーム       | 同一タスクを複数プロジェクトで共有                         |
| コミュニケーション | タスクのコメント、承認申請・承認・差し戻し                 |
| 通知               | 担当者の割り当て、コメント、承認依頼・結果をアプリ内で通知 |
| 社内フォーム       | ログインしたメンバーの依頼をタスクとして登録               |
| カスタムフィールド | プロジェクト設定からテキスト・数値・選択肢を追加           |
| 自動化             | ステータス変更時に担当者と期日を更新                       |
| Google連携         | Drive資料URL、Calendar予定の作成画面、ICS出力              |
| アカウント         | 管理者による発行・利用停止、自分のパスワード変更           |

ボードのカード下部にもステータス選択欄を用意し、スマートフォンやキーボードでも変更できます。タイムラインは表示期間を2週間ずつ移動でき、期日なしのタスクは下部に表示します。依存線は両端が表示期間内にある場合に表示されます。依存関係は可視化用で、タスク着手のブロックや日程の自動調整は行いません。

他のメンバーの更新は15秒ごとに取得します。自分の操作は保存後すぐ反映されます。タスクには更新バージョンを持たせ、同時編集による古い内容での上書きを防いでいます。

自動化は既存タスクのステータス変更時に実行します。複数プロジェクトに属する場合、所属順・ルールの登録順に適用し、後のルールの設定が優先されます。期日ルールが開始日より前の日付を設定する場合は、開始日も期日に合わせます。

## Google Workspaceとの連携

初版は認証情報なしで使えるリンク・ファイル連携です。

- **Drive**: タスク詳細の「依存関係・資料リンク」でドキュメントなどの共有URLを追加します。閲覧権限はDrive側の共有設定に従います。
- **Calendar**: 期日を設定したタスクから「Google Calendarに追加」を押すと、タイトル・説明・日付を引き継いだ予定作成画面が開きます。Google側で保存を確定してください。
- **ICS**: 「ICSを保存」でカレンダーファイルをダウンロードできます。Google Calendarなどのインポート機能で取り込めます。

Google OAuth/SSO、Driveのファイル検索、カレンダーの自動同期・双方向同期は含みません。タスクの期日を後から変更した場合、Google側の予定も手動で更新してください。将来Calendar APIへ拡張する場合は、[Google公式のOAuth手順](https://developers.google.com/identity/protocols/oauth2/web-server)と[予定作成API](https://developers.google.com/workspace/calendar/api/guides/create-events)に従って、Workspace管理者がOAuthクライアントと許可スコープを設定します。

## 社内共有・クラウド運用

初期状態の `127.0.0.1` はこのPCからだけ接続できます。社内メンバーが別のPCから利用するには、社内サーバーまたはクラウドのVMに配置し、HTTPSで共有する必要があります。クラウド契約・公開先・ドメインが指定されていないため、現時点で外部へのデプロイは行っていません。

Docker用の構成を同梱しています。永続ディスクを利用できる単一のLinux VMとドメインがある場合の例です。

1. このフォルダーをサーバーへ配置し、Docker Composeを準備します。
2. `.env` に以下を設定します。

```dotenv
APP_DOMAIN=work.yourcompany.co.jp
ALLOWED_EMAIL_DOMAIN=yourcompany.co.jp
SETUP_TOKEN=replace-with-a-long-random-secret
```

3. ドメインのDNSをサーバーに向け、80/443番ポートを利用できるようにします。
4. `docker compose up -d --build` を実行します。
5. `https://work.yourcompany.co.jp` で初期設定し、設定した初期設定トークンを入力します。

同梱のCaddyがHTTPSを終端し、アプリの3000番ポートは外部に公開しません。本番モードではSecure Cookieを使用します。社内限定のネットワーク要件がある場合は、VPN・社内ネットワークへの接続制限もサーバー側で設定してください。初期設定後は `SETUP_TOKEN` を変更・削除しても既存ログインは継続できますが、Composeを使用する間は環境変数の必須設定を満たしてください。

本構成はSQLiteを使う単一インスタンス向けです。複数台の水平分散、サーバーレスの一時ディスクにはそのまま配置できません。Docker/クラウド環境の動作は、このWindows PC上では検証していません。

## データの保守

- ローカル保存先: `data/worknest.sqlite`（SQLiteのWAL/SHMファイルも生成されます）
- Docker保存先: `worknest_data` ボリュームの `/app/data`
- パスワード: scryptハッシュとして保存。平文のパスワードは保存しません。
- セッション: HttpOnly Cookieとサーバー側のハッシュ化セッション。有効期限は12時間です。
- データフォルダーには社内情報と認証情報が含まれるため、サーバー管理者だけが直接アクセスできるようにしてください。

**バックアップ**: `npm.cmd run backup` で稼働中でも整合性のあるSQLiteを `data/backups` へ追加できます。[保存先・復元方法](docs/release-guide.md#稼働中のバックアップ) を参照してください。`data` はGit対象外です。

**パスワードを忘れた場合**: サーバーにアクセスできる管理者が、サーバーを停止して次を実行します。入力したパスワードは画面に表示されません。

```powershell
node --env-file-if-exists=.env scripts/reset-password.mjs admin@yourcompany.co.jp
```

指定ユーザーの全セッションが失効し、次回ログインでパスワード変更が必要になります。対象を問わず、このコマンドの実行にはサーバーのファイルアクセス権が必要です。Dockerでは `docker compose exec -it app node scripts/reset-password.mjs ...` で実行できます。

## 開発・検証

```powershell
npm.cmd run dev      # API :3000 / 画面 :5173
npm.cmd run check    # TypeScript
npm.cmd test         # 認証・権限・主要業務フロー・永続化
npm.cmd run build    # dist に本番画面を生成
npm.cmd run test:browser # タスク・営業の実ブラウザー検証
npm.cmd run check:publish # 公開対象にDBや秘密鍵形式がないか確認
```

ブラウザー検証は独立した一時DBを使い、実データを変更しません。Windowsでは標準パスのChromeを使用します。他の環境では `npx playwright install chromium` でブラウザーを準備してください。任意の実行ファイルは `BROWSER_EXECUTABLE_PATH` で指定できます。

```
src/                  React画面・型・スタイル
server/index.mjs      HTTPサーバー・認証・業務API
server/store.mjs      SQLite・パスワード・サンプルデータ
tests/api.test.mjs    APIの統合テスト
docs/requirements.md 要件定義・受入基準
scripts/              開発起動・パスワード復旧
```

基盤には[Node.js標準のSQLite API](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)を利用しています。高度なAIエージェント、Slackへの送信、公開フォーム、添付ファイルアップロード、細かなプロジェクトアクセス権は今回の実装範囲外です。
