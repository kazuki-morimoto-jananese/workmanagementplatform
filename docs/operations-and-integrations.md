## 今回の確認結果と変更

| 確認項目                   | 対応                                                                                                                 |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 数字・議事録・タスクの蓄積 | SQLiteに永続保存。従来の操作履歴500件制限を撤廃し、主要データの作成・更新・削除の前後を監査テーブルへ保存            |
| Googleドキュメント         | URLから本文を取得。議事録詳細から任意のタイミングで再取得。手入力・TXT/MD追加も継続                                  |

## 保存と復元

- `DATA_DIR/worknest.sqlite`に数字の月別・週別データ、原文、要約、抽出結果、タスク、コメント、担当者、組織を保存します。再起動やブラウザーを閉じても残ります。
- `audit_log`はタスク、プロジェクト、アカウント、マスタ、ヨミ、商談、議事録、営業行動、組織、設定、メンバーの変更前後と日時・実行者を保存します。書き込みと監査は同じトランザクションです。ユーザーのパスワードハッシュやセッショントークンを監査ログに含めません。
- 更新前後の完全な保存はv2.3導入時点からです。導入時のデータを基準状態として保存します。過去に既に削除された500件より前の操作履歴や上書きされた内容は復元できません。
- 管理者は「設定・連携」で全社監査を100件ずつ遡れます。タスク・議事録詳細では対象レコードの履歴を閲覧できます。表示分をJSON保存できます。CSVは従来通り営業画面から出力できます。
- 履歴とバックアップの自動削除はありません。バックアップはサーバー稼働中、初回および最終実行から24時間経過後に`data/backups`へ作成し、SQLiteの整合性を検査します。停止中は実行されません。
- 「今すぐバックアップ」または`npm.cmd run backup`でも実行できます。作成日時と失敗状態は管理画面へ表示します。同一ディスクへの保存だけではディスク故障を防げないため、別ストレージへの定期複製と容量監視を運用してください。
- 削除されたタスクの元データも監査に残ります。画面のごみ箱・個別復元は未実装です。全体の復元には次のコマンドを使います。

```powershell
npm.cmd run restore -- "data/backups/実際のバックアップ名.sqlite" "data-restored"
```

復元先は空のフォルダーに限ります。既存DBを上書きしません。復元後はサーバーを停止し、`.env`の`DATA_DIR`を復元先へ変更して起動します。ユーザー情報は保持し、過去のセッションは無効化するため再ログインが必要です。復元先にも実データが含まれるためGitへ追加しないでください。旧バージョンのバックアップも起動時に監査の保存を開始します。

## 組織と共同作業

「メンバー」の「組織と所属」で会社から順に登録します。同じ親組織での重複名と階層の飛び越しを拒否します。組織IDが共通なので名称変更は各画面の表示へ反映されます。既存のスプレッドシート上の担当グループ名は取込元情報として保持し、共通組織を選ぶと営業画面の組織表示にはそちらを使います。名称からの推測による自動所属は行いません。

プロジェクト設定で担当組織と参加者を選択できます。プロジェクト一覧の表示切り替えで参加・担当分だけを表示できます。ショートカットも参加・担当分を優先し、7件での打ち切りを廃止しました。**組織と参加者は分類・発見用です。現在のワークスペースは全メンバー共有で、プロジェクトの閲覧制限ではありません。**

タスク詳細のチェックボックスで複数担当を選べます。先頭の担当者を一覧の代表表示にし、追加人数を表示します。既存の自動化で担当者を設定する際は、その担当者を先頭へ追加し、共同担当者を保持します。

## Googleドキュメントの設定

1. Google CloudでGoogle Drive APIを有効にします。Sheets連携用サービスアカウントを共用できます。
2. サービスアカウントのJSON鍵をGit管理外のサーバーに配置し、`GOOGLE_SERVICE_ACCOUNT_FILE`へパスを設定してサーバーを再起動します。秘密鍵をチャット・ブラウザー・Gitへ入力しません。
3. 読み込み対象の議事録をサービスアカウントのメールアドレスへ閲覧共有します。Google Workspaceでこの共有が制限される場合はWorkspace管理者による共有ポリシーの設定が必要です。
4. 「営業・数字管理」→「議事録を保存」→登録方法「Googleドキュメントを読み込む」でURL・対象アカウント・商談日・数字の対象月・反映先の会議週を指定します。
5. 変更後は議事録詳細の「Googleから更新」を押します。変更がなければ取得日時を更新し、変更があれば新しい改訂版を作ります。旧版の原文・要約・数値抽出結果・タスクは残り、改訂前後へ移動できます。

取得はDrive APIの読み取り専用スコープで行い、Googleの文書には書き込みません。対応はGoogleドキュメントのプレーンテキスト出力、最大80,000文字です。画像・コメント・書式は取り込みません。フォルダーの自動巡回とユーザーごとのOAuth接続は未実装です。URLはGoogle公式ドメインに限定し、取得先は固定APIです。同じアカウントに同じ文書を重複登録できません。

接続アカウントが読める文書の本文は、取り込むとWorknestの全メンバーに共有されます。個人だけが閲覧する文書の保管場所としては使わず、全社共有してよい議事録を対象にしてください。外部共有できない場合の[Google本人認証](google-user-connection.md)を追加しています。タスクは個別に[非公開設定](task-options.md)ができます。

## Geminiによる数値入力

`.env`へ`GEMINI_API_KEY`と`GEMINI_MODEL`を設定して再起動します。APIキーはサーバーのみで使用します。無料枠を利用できるモデルと割当量は[Google公式の料金表](https://ai.google.dev/gemini-api/docs/pricing)で確認してください。Google側の利用枠は変更されるため、このアプリは無料での実行を保証しません。Google側の課金と割当量を確認して利用してください。

議事録には「2026年9月、A社、スタンバイ着地ヨミ300万円、Indeed予算500万円、消化額200万円、CPA1,500円」のように、対象月・会社・媒体・項目・単位を明記すると取り込みやすくなります。

- 保存後の自動抽出と、任意の「Geminiで数値を抽出」を利用できます。抽出はバックグラウンドで処理し、サーバー再起動後も未完了の処理を再開します。
- 対象はヨミ、アグレッシブ、確度、許容CPA、3媒体の予算・消化額・応募数・CPA・採用数・継続月数です。Gトレとヨミ、予算と消化実績は別項目として扱います。
- 抽出値は円へ換算し、数値・単位・引用が原文と一致することをサーバーで検証します。引用のない値、異なる対象月、重複項目、不正な件数を拒否します。意味の解釈まで完全には保証できないため、初期状態は確認して反映する方式です。
- 「当月の抽出値を未入力欄に自動反映する」を選ぶと、登録した当月の会議週へ自動入力します。入力済みの値は0円も含めて保持し、推測値による上書きはしません。空欄を持たない場合は反映なしと表示します。
- 手動反映時はヨミの版数を検査し、別の人が更新した場合は再確認を求めます。反映した値・保持した項目・実行者・原文との紐づけを保存します。改訂版の抽出は再確認でき、以前の反映履歴も残ります。
- `GEMINI_DAILY_EXTRACTIONS=20`、`GEMINI_DAILY_SUMMARIES=20`が初期上限です。日本時間の日付ごとに記録し、失敗も回数に含めます。429などの失敗時は既存の数字と本文を保持し、画面から再試行できます。他モデルや有料APIへの自動切り替えはありません。
- **無料枠は入力データがGoogleの製品改善に利用される条件があります。** 実顧客の機密情報に使う前に[料金表とデータ利用条件](https://ai.google.dev/gemini-api/docs/pricing)を確認してください。API未設定時の要約はローカル抽出で、AI数値抽出は無効です。

実サービスへの疎通には利用者のGoogle設定が必要です。開発テストは通信を模した応答で実施し、顧客のDriveやGeminiへ実データは送信していません。
