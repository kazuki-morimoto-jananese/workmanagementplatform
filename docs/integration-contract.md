# 外部データ連携契約 v1

営業・数字管理 → データ連携 → 汎用連携で管理者が受付トークンを発行します。今回の共通APIは**顧客担当者の受付専用**です。売上・タスク・議事録の汎用同期APIや、各製品の完成済みコネクターではありません。

## 送信方法

`POST https://YOUR-WORKNEST/api/integrations/v1/contacts`

ヘッダー：`Content-Type: application/json`、`X-Worknest: 1`、`Authorization: Bearer トークン`。
ブラウザーにトークンを埋め込まず、連携元のバックエンド、Apps Scriptのスクリプトプロパティ、シークレット管理に保存します。外部サイトからのブラウザー直接送信は対象外です。

```json
{
  "requestId": "crm-export-20260907-001",
  "contacts": [{
    "externalId": "contact-001",
    "name": "サンプル担当者",
    "company": "サンプル企業",
    "email": "sample@example.com",
    "campaign": "秋の展示会",
    "stage": "new",
    "consent": "unknown",
    "nextContact": "2026-09-15"
  }]
}
```

1回1〜50件、本文128 KiB以下、トークンあたりUTC日付で100受付/日。氏名と外部IDは必須。氏名等の短文は200文字、notesは3,000文字までに整形してください（超過分は切り詰め）。requestIdは100文字以内、externalIdは200文字以内。同じ受付内の外部ID重複はエラーです。

任意項目：accountId（登録済み営業アカウントID）、ownerId（有効な社内メンバーID）、notes。stageはnew / qualified / negotiating / customer / lost、consentはunknown / allowed / denied。営業段階の運用基準は各社で合意してください。連絡許可はこの入力だけで法的な同意の証明にはなりません。必要な証跡をメモ・元システムに保存します。

## 反映と更新

- 202：受付済み。管理者の「確認して反映」で初めてCRMへ反映。
- 200：同一requestId・同一内容の再送。新規に作成しません。
- 400：入力不備、404：未対応API。401：トークン不正・失効・期限切れ・発行者無効。
- 409：同一requestIdで異なる内容、または受付後に手入力で更新済み。新しいrequestIdで再受付し、管理者が差分を確認。
- 413：本文上限、429：日次上限。ネットワーク障害や5xxは同じrequestId・同じ本文で時間をあけて再送。

外部IDは連携元ごとの名前空間です。同じ顧客を異なる連携元で送信すると別のレコードになるため、ID統合・名寄せは連携側で行います。「トークンを更新」は名前空間を引き継ぎ、以前のトークンを失効させます。新しく発行すると別の連携元になります。発行時・更新時のみ秘密値を返し、保存はSHA-256ハッシュのみ。有効期限90日。無効化された管理者のトークンも使用できません。

省略した項目は既存値を維持し、明示した空文字は消去として扱います。sourceはトークンの連携元名になります。人の編集との競合はversionで検知し、バッチを丸ごとロールバックします。受付・反映・却下履歴、顧客の変更前後を永続保存します。不正トークン等の未受付リクエストは業務履歴に保存しないため、送信側もHTTP結果を記録してください。保存データの自動削除はありません。

## Google Formsの連携例

`integrations/google-forms.gs` をフォーム回答先スプシの Apps Script に配置します。
スクリプトプロパティに WORKNEST_ORIGIN（末尾スラッシュなし）と WORKNEST_TOKEN を保存し、スプレッドシートの「フォーム送信時」インストール型トリガーに sendContactToWorknest を指定します。
フォームの見出しは「氏名」「会社名」「メールアドレス」「施策名」「連絡許可」に合わせるか、スクリプトの対応名を変更してください。同意選択肢「同意する」の場合のみallowed、それ以外はunknownです。

これは会社内の実行者権限で動く送信例です。Worknestへの外部送信が会社で許可される必要があります。外部共有禁止ポリシーを回避する方法ではありません。配備・トリガー認可・実データ送信は未実行。トリガー失敗時はApps Scriptの実行履歴で確認し、同じ送信IDで復旧します。Sheetsマスタの既存日次同期とは別の機能です。
