# 会社・部内で試験運用を始める

## 組織と上司の登録

管理者でログインして「メンバー」→「組織と所属」を開きます。会社、事業部、部署、チームの順に作成します。同じ部署の複数チームは、親組織に同じ部署を選んで登録します。

例（実際の正式名称へ置き換え）:

```text
会社
└ 営業事業部
  └ 総合企画部
    ├ 自分のグループ
    └ 他のグループ
```

登録後「自分の所属」で所属チームを選びます。管理者は他メンバーの所属も選べます。会社全員を招待する必要はありません。最初は部内の本人と上司だけをメンバー登録できます。現構成では、登録された全メンバーがワークスペース全体を共有します。組織の登録だけではメンバー発行や閲覧制限は行いません。

上司は「メンバーを追加」で会社メール・名前・仮パスワードを登録し、権限を「管理者」にします。既存メンバーは一覧の権限欄から変更できます。管理者はメンバー・組織・連携設定・監査履歴を管理できます。単にタスクの承認を依頼する場合は、メンバー権限のまま承認担当へ指定できます。仮パスワードは社内で安全に共有し、初回ログインで本人が変更します。メールによる招待の自動送信はありません。

## 個人開発から会社用へ

GitHubアカウントはソースの所有者であり、Worknestのログインユーザーとは独立しています。会社用環境を空のDBで起動し、会社名をワークスペース名にして初期管理者を会社メールで作成できます。現構成は**1つの稼働環境に1ワークスペース**です。1つのURL内で個人用と会社用を切り替える機能はありません。

会社用のサーバー・永続ボリューム・Google接続用サービスアカウントを用意し、個人PCのデモDBをコピーせずに開始します。GitHubは非公開のままで構いません。必要に応じて後から会社管理のGitHub組織へリポジトリを移管できます。会社の実データを保管するサーバーとGoogle Cloudプロジェクトは、会社で管理できるものを使ってください。

## 公開の順番

1. **公開先とURLを決める**：常時起動のLinuxサーバー、永続ディスク、Docker Compose、公開ドメインを準備します。アプリのスケジューラーとSQLiteを使うため、この構成は常時稼働する単一インスタンス向けです。
2. **DNSとHTTPS**：`worknest.example.com`などのDNSをサーバーへ向け、80/443番ポートを到達可能にします。Caddyが証明書の発行・更新を行います。詳細は[Caddy公式資料](https://caddyserver.com/docs/automatic-https)。GitHub PagesにはこのAPIとDBを配置できません。
3. **非公開ソースを配置**：対象サーバー上で非公開リポジトリをcloneします。GitHubの認証はサーバーで利用できる読み取り専用の認証方法を設定します。ソース・`.env.company`・Google鍵に実データのDBを混ぜません。
4. **会社用設定を生成**：以下を実際のドメインで実行します。Node.js 24が必要です。初期設定トークンはランダム生成され、画面には出さず`.env.company`に保存します。既存ファイルや既存DBは上書きしません。

```sh
node scripts/prepare-company.mjs worknest.example.com example.com
```

5. **起動**：リポジトリのルートで次を実行します。`worknest-company`というプロジェクト名で会社用の永続ボリュームを作ります。ローカルPCの`data`とは別の保存先です。

```sh
docker compose --project-name worknest-company --env-file .env.company -f compose.yaml up -d --build
```

6. **会社用ワークスペースを初期登録**：公開URLを開き、会社用ワークスペース名・本人の会社メール・パスワードを入力します。初期設定トークンはサーバーの`.env.company`をローカルに確認して入力します。サンプルデータはオフにします。
7. **部内メンバーを登録**：組織を登録し、上司・必要なメンバーだけを追加します。未登録の人はログインできません。設定した会社メールドメイン以外での新規登録を拒否します。Google SSOではなく、Worknestのメール＋パスワードによるログインです。
8. **バックアップを確認**：「設定・連携」から手動バックアップを実行します。自動バックアップは同じ永続ディスクへ保存されるため、別ストレージへの複製と空き容量の監視も設定します。`docker compose down -v`は会社の永続データを削除するので使用しません。

Composeの`.env.company`読み込みは[`--env-file`の公式仕様](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/)に従います。設定生成だけではサーバー契約、DNS設定、インターネットへの配置は行いません。

## 参考スプシを実際に連携する

1. 会社管理のGoogle CloudプロジェクトでGoogle Sheets APIを有効化し、サービスアカウントを作成します。
2. 対象スプシを、そのサービスアカウントのメールアドレスへ**閲覧者**として共有します。Workspaceの共有制限がある場合は、会社のGoogle管理者による設定が必要です。これはWorknestの管理者権限とは別です。
3. サーバー上の`.secrets/google-service-account.json`へ鍵を配置し、コンテナの実行ユーザーが読み取れるようにします。現在のDockerイメージは`node`ユーザー（UID/GID 1000）で動きます。Linuxでは`.secrets`の所有者をこのユーザーにし、ディレクトリは700・鍵は600などに設定します。ファイルだけでなく親ディレクトリにもアクセス権が必要です。鍵やAPIトークンはチャット・Gitへ貼り付けません。Googleドキュメントも使う場合はDrive APIを有効化して、対象文書も共有します。
4. Google連携用のCompose設定を追加して起動し直します。同じプロジェクト名・同じボリュームを使います。

```sh
docker compose --project-name worknest-company --env-file .env.company -f compose.yaml -f compose.google.yaml up -d --build
```

5. Worknestの「営業・数字管理」→「データ連携」でスプシのIDと取得範囲を保存します。IDはURLの`/d/`と次の`/`の間、範囲は例として`'連携用マスタ'!A1:AZ5000`です。初回確認中は日次同期をオフにします。
6. 「保存済み接続をプレビュー」でGoogle上のデータを確認します。この操作では業務データを更新しません。アカウントIDの重複や数値エラーがないことを確認します。列の名称が異なる場合は、CSV/TSV取込プレビューの列対応を修正し、「確認済みプレビューの列対応を日次同期にも適用」で保存します。
7. 「今すぐ同期」で初回取込し、件数、Gトレ、予算、媒体の消化額・CPAを確認します。金額は円、空欄は未入力、0は実際の0として扱います。「予算」と「消化額」を同じ列に対応させないでください。
8. スプシの更新完了後の時刻を設定し、「日次同期を有効にする」を保存します。例：元データが9時に更新完了するなら9時30分に設定します。

参考に受け取った見出し（アカウントID、当月担当者、今週Gトレ、3媒体の予算・消化額・CPAなど）は対応済みです。ただし受領した抜粋は接続そのものではありません。実際のURL、タブ名、共有権限の設定と初回プレビューが必要です。結合見出し・途中の空行・重複IDがある場合は、先頭行を1行の見出しにした連携用タブを用意してください。

現在、日次同期の接続先は**1つのスプシの1つの範囲**です。複数ファイルに分かれている数字を同時に取り込む場合は、スプシ側でアカウントIDをキーに連携用タブへ集約します。毎月自動切り替えは取込対象月の指定を切り替える機能です。スプシ内のタブ名・範囲は自動では切り替わらないため、同じ連携用タブに当月データが並ぶ構成にしてください。

## 日次・任意の更新の動き

- 自動同期は設定した日本時間以降に1日1回実行します。判定間隔は1分なので指定時刻から最大約1分ずれる場合があります。サーバー再起動が設定時刻を過ぎた場合、その日の未実行分を取り込みます。
- 「今すぐ同期」は管理者が任意のタイミングで実行できます。手動同期しても、その後の当日の日次同期は省略しません。
- スプシを編集した瞬間に通知を受けて反映する方式ではありません。スプシの更新完了後に同期時刻を設定してください。
- 同期対象はアカウントと月次マスタです。Worknestで入力したヨミ・競合の週次入力・議事録・タスクは保持します。Googleスプシへの書き戻しはしません。元データから消えたアカウントも勝手に削除しません。
- 失敗した場合は既存データを保持し、最終成功日時とエラーを表示します。その日の自動再試行は行わないため、原因を直して「今すぐ同期」で再実行できます。

読み取り権限は[Google Sheetsの読み取り専用スコープ](https://developers.google.com/workspace/sheets/api/scopes)を使用します。認証は[サービスアカウント方式](https://developers.google.com/identity/protocols/oauth2/service-account)です。Geminiはスプシ連携には不要なので、まずGemini未設定で上司との数字管理を開始できます。
