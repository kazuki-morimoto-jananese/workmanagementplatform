# 担当・グループ変更と引き継ぎ

管理者の「営業・数字管理 → 担当・引き継ぎ」から操作します。半期で担当・グループが変わる運用と、例外的な月途中の変更に対応します。一般メンバーは適用後の担当一覧を利用できます。

## 読み込みと確認

1. 担当変更表のURLまたはID、タブ名、見出し行、最終列を設定します。既存のGoogle本人認証（スプシ閲覧）を使用します。Google上の権限を増やす必要はありませんが、接続者に対象ファイルの閲覧権限が必要です。
2. 「接続設定を保存して読み込む」を押すか、Excel / CSV / TSVを選びます。Googleは500行単位、最大20,000行を取得。途中の空白行・空白区間でも打ち切りません。最大41回のSheets取得になるため、他の同期と重なるとGoogleの利用制限で再試行が必要な場合があります。
3. 使用する列を確認します：アカウントID、アカウント名、前月担当Ｇ、前月担当者、当月担当Ｇ、当月担当者。見出し名が違う場合は手動で列を対応させます。Excelは10MB、既存の読取処理の上限50万セルまで。対象タブ・必要列だけのファイルを推奨します。
4. **担当変更の適用日を明示的に入力**します。AP適応日などの別の日付からは推測しません。
5. 担当者名・グループを既存のメンバー・組織マスタに紐付けます。同名が一意なら自動対応。別表記は選択式で指定できます。後任が未登録なら名前を保存し、「メンバー紐付け待ち」として表示します。メンバーアカウントの自動作成・招待はしません。
6. 「担当変更の差分を確認」で変更前後を表示。ID・名前・担当者・グループで検索し、後任別に絞り込めます。必要なアカウントを選択して反映します。

**アカウントIDが一致する既存の実アカウントだけが対象**です。新規アカウントはこの画面で追加せず、「アカウントマスタ」等で先に登録してください。デモ・ID重複・後任空欄・未対応の当月グループは反映対象外です。

当月担当Ｇが空欄の場合は変更前のグループを保持します。後任ごとのグループを明示的に指定して補うこともできます。アカウントの管理グループと社員本人の所属は別情報です。社員の所属変更は「メンバー」、月別の個人目標・所属計画は既存の目標画面で管理します。

## 適用日と履歴

- 登録したアカウントは、当月は日本時間の本日時点、過去・未来の月は月末時点の担当を表示します。未来月は予定を含みます。月途中の配賦・担当者別売上の日割り計算は行いません。
- 月初変更の初回登録で前月担当者が記載されている場合、前月1日からの履歴も保存します。これは表の前月担当を月単位で採用するものです。前月の途中でも変更があった場合は、適用日別に登録してください。
- 未来日を初めて登録する場合、前月担当が使えなければ本日の現担当を保存し、適用日前に現担当が消えないようにします。既知の履歴より古い期間の担当は「未登録」として扱い、現在の担当を遡って付与しません。
- 同じアカウント・同じ適用日は修正扱いです。修正前後は監査ログへ残ります。別の適用日は新しい履歴として追加します。既に登録済みの将来日の予定を自動修正することはありません。
- 履歴登録後は営業マスタの再取込・通常のアカウント編集から担当者・グループを上書きしません。売上・Gトレなどの数字の同期は引き続き利用できます。担当の修正は本画面で行ってください。
- 営業サマリー・週次ヨミ・議事録・顧客カルテ・商談準備の担当フィルター、アカウントマスタ、週次CSV、営業会議資料が同じ担当履歴を参照します。固定の組織KGIサマリーは元スプシの値を保持します。

## 仕事の引き継ぎ

「保存履歴・仕事の引き継ぎ」で保存回とアカウントを選びます。アカウントは名前・IDで検索できます。履歴は30回ずつ追加取得できます。

現在有効な担当変更で、後任が有効メンバーに紐付いていれば、前任が持つ公開の未完了タスクと未受注・未失注の商談を選択して引き継げます。1回50件、候補表示500件。500件を超える場合は引き継ぎ後に再取得して続けられます。

複数担当タスクでは前任だけを置き換え、共同担当者を保持します。同日の担当修正時には、修正前の担当者も引き継ぎ元として保持します。完了タスク・非公開タスク・受注済み／失注済み商談は変更しません。顧客担当者（連絡先）の社内窓口、承認者、プロジェクト責任者などは自動変更しないため、必要に応じて個別に確認してください。

議事録・分析・施策・カルテはアカウントIDに紐付いたまま残り、作成者は変わりません。Drive原本へのアクセス権はGoogle側で別途管理してください。

## 保護と無料運用

- 確認・反映は100件単位。確認後にアカウント・担当・組織が変わると反映を止め、再確認を求めます。同じ保存リクエストの再送は重複登録しません。
- 各100件の保存はトランザクションです。全体の途中で失敗した場合は、それまでの保存が残ります。履歴を再取得し、差分を確認し直して続行してください。
- 担当履歴・設定・反映履歴・変更した仕事には監査記録を残し、既存の全データエクスポートに含めます。履歴の表示件数は保存期限ではありません。既存のバックアップ／復元運用を継続してください。
- 生のExcelファイルはサーバーに保存しません。担当履歴と変更に必要なデータだけを保存します。新しい有料サービス・AI API・定期ジョブは追加していません。Cloudflareの契約枠内での運用を想定し、アカウント／適用日・保存履歴の索引と、対象アカウントだけの仕事検索を使用します。利用量が増えた場合の上限は既存の「使用状況」で確認してください。
