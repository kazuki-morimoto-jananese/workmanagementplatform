# 営業・数字管理 v2

> v2.3のGoogleドキュメント取込・数値抽出・長期保存・組織・複数担当の仕様は[運用・連携ガイド](operations-and-integrations.md)を参照してください。以下の初期仕様より新しいガイドが優先します。

## 今回整理した課題と対策

| 課題                                           | Worknestでの対策                                                                                       |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| アカウント名の表記ゆれで表がつながらない       | スプシのアカウントIDを文字列で保持。ヨミ・媒体指標・商談・議事録・タスクが同じIDでつながる             |
| 日次マスタ更新で営業の入力が消える             | マスタと週次入力を別保存。マスタ同期ではヨミ・根拠・商談・議事録を上書きしない                         |
| 前週のヨミが上書きされ、差分の理由がわからない | 対象月＋月曜日の週次スナップショット、同じ週の変更履歴、更新者、根拠を保存                             |
| 空欄・0円・未更新が混在                        | 未入力はnull、0円は0。Gトレ0円とヨミの乖離、入力率、マスタ鮮度を表示                                   |
| 自社実績・競合予算・商談金額が混ざる           | 自社とIndeed・求人BOX、予算と実消化額、月次ヨミと案件パイプラインを別管理                              |
| ヨミ根拠や顧客接点が担当者の頭の中にある       | 根拠必須入力、目標・課題・ファネル・有効提案・予算動向を週次に記録。14日超の接点未記録を表示           |
| 議事録が個人フォルダーに散らばる               | アカウントに紐づけて原文を格納。テキスト貼り付け・.txt/.md読込・元資料URLに対応                        |
| AIが推測した内容が勝手にタスク化される         | 原文の根拠と提案を表示。担当者・期限・プロジェクトを人が選んだときだけ作成。アクション単位で重複を防止 |
| 複数人の編集が競合する                         | 更新バージョンを検証し、古い画面からの上書きを拒否                                                     |
| 同期失敗やAIの失敗に気づけない                 | 成功時刻・エラー・取込件数、要約の待機／処理中／失敗を保存・表示。原文は失敗しても残る                 |

## 最初に使う

1. いつものアカウントでログインし、左側の「営業・数字管理」を開きます。
2. 「データ連携」で、スプシの見出し行を含めたコピーを貼り付けるか、CSV/TSVを選択します。
3. 対象月を確認し、「取込内容を確認」でID・名前・金額・警告を確認します。列の対応は変更可能です。
4. 管理者が「この内容で取り込む」で確定します。架空データで試す場合は「3か月デモを追加」を押します。実データがある場合も、表示を分けて使用できます。[デモの見方](demo-guide.md)。
5. 「週次ヨミ」で対象月と会議週を選び、各アカウントの入力を保存します。

添付いただいた42列・4アカウントのTSVについて、引用符付き改行セルを含め解析エラーなしで読み取れることを確認しました。参考資料を本番データへ自動投入していません。取込元にしかない補足列も原文として保存し、アカウントの入力画面で確認できます。

初回移行でスプシの既存ヨミを引き継ぐときだけ、「未登録の当週ヨミだけスプシから補完する」を有効にしてください。すでに入力済みの当週ヨミは変更されません。移行元の根拠が空欄の場合はそのまま保存し、画面で未記載を明示します。通常の週次入力では、金額を入れたら根拠も必須です。

当月担当者名が社内メンバー名またはメールと一意に一致する場合に紐づけます。一致しない場合は取込名をそのまま保持し、「アカウント・担当者設定」からログインメンバーを明示的に選択できます。アカウントIDは先頭の0も保持します。元のSheetsで数値型になって消えた先頭0を復元することはできません。

## 数字の定義

- **Gトレ**: 当月の消化額の着地予測。ユーザー確認済み。円で保持します。
- **担当者ヨミ**: 担当者が見込む、その月全体の着地。対象月・選択週以前の最新レコードをアカウントごとに1件集計します。前週入力の引き継ぎは「当週入力済み」に含めません。
- **前週差**: 選択週のヨミ − その前の月曜日時点で登録されていた最新週のヨミ。比較値がない場合は「—」。同じ週の改訂は変更履歴で確認します。
- **アグレッシブ**: 条件が成立した場合の強気の月間着地。ヨミ以上の数値を入力します。根拠と条件はヨミ根拠欄へ記録します。
- **確度加重パイプライン**: 受注予定月が対象月の商談金額×受注確度。月次ヨミには加算しません。受注は100%、失注は0%です。
- **予算と消化額**: 別の項目です。スタンバイ予算を実績として扱いません。競合の消化額も自社実績へ加算しません。
- **サマリーの消化実績**: 日次マスタのスタンバイ消化額を優先し、その値が未取得の場合だけ選択週以前の媒体入力を使用します。媒体の取得日も合わせて確認してください。
- **CPA**: 消化額÷実測CV。実測CVがない場合は入力されたCPAを参考値として保持します。0で割らず、予算からCPAを推測しません。
- **採用単価**: 消化額÷採用数。分母が0／不明の場合は計算しません。
- **目標との差**: 目標とヨミが表示対象全件で揃う場合に算定します。欠損を0とみなしたギャップは表示しません。
- **行動KPI**: 当月の架電・商談／訪問・提案の記録件数。議事録登録数を商談件数に自動加算しないため、二重計上を避けられます。

スプシの「確度A/B/C」は、社内で定義が異なる可能性があるため勝手に割合へ変換しません。元の列を保存し、Worknestでは0〜100%で明示入力します。粗利・会計売上・売上計上日が元データにないため、消化額を会計売上と同一視する処理は実装していません。

## 週次会議の進め方

v2.1では営業入力を閉じる・Escapeを押す・関連設定へ移動する際に、未保存の変更があれば画面内で確認します。媒体の計算CPA・採用単価は入力中に更新されます。議事録はタイトル・本文・アカウント名で検索できます。ブラウザーの再読込をまたぐ下書き保存は行わないため、会議中も区切りごとに保存してください。

1. 営業サマリーで当週入力率、Gトレとヨミの差、未取得の数字を確認。
2. 週次ヨミで今月または翌月を選択し、ヨミ・根拠・アグレッシブ・今週やることを保存。
3. 媒体別の予算、消化額、CV、CPA、採用数、許容CPAと取得日を記録。
4. 商談で受注予定日・フェーズ・確度・次の行動を更新。
5. 議事録を保存し、要約の決定事項とアクション案を原文と照合。
6. 必要な行動だけタスクにして、既存のリスト・ボード・タイムラインで進める。

初期表示では現在のステータスが「解約」「停止」「休止」「利用停止」のアカウントを集計から除きます。「すべての状態」へ切り替えると過去の入力も確認できます。週次CSVは選択中の「実データ／デモ」に属する全アカウントを出力し、それ以外の検索・担当者・状態による絞り込みは適用しません。

セグメント別のCPA（看護師／介護など）は、同じ対象範囲・期間で比較する必要があります。初版の数値欄はアカウント単位です。細かなセグメントは顧客目標・課題・議事録・取込元原文へ保持し、異なる範囲のCPAを混ぜて判断しないでください。

## Google Sheetsの日次取得

現在の実装は**読み取り専用、1つの定期同期元**です。複数のスプシからの手動取込には対応しており、今回取り込んでいない列は既存値を保持します。毎日の自動取得を一元化する場合は、必要なマスタ列をまとめたタブを作る運用を想定しています。

1. Google Cloudでプロジェクトを作成／選択し、Google Sheets APIを有効化します。
2. サービスアカウントを作成し、JSON形式の鍵をサーバーへ配置します。例: `.secrets/google-service-account.json`。
3. 取得するスプシを、そのJSONの `client_email` に「閲覧者」として共有します。スプシの一般公開は不要です。
4. `.env` に以下を設定してサーバーを再起動します。

```dotenv
GOOGLE_SERVICE_ACCOUNT_FILE=C:/work/workmanagementplatform/.secrets/google-service-account.json
```

5. Worknestの「データ連携」でスプレッドシートID、見出し行を含む範囲（例 `営業マスタ!A1:AZ5000`）を保存します。
6. 「保存済み接続をプレビュー」でGoogle上のデータを確認し、「今すぐ同期」で初回の取込を実行します。スプシの更新が完了した後の同期時刻を設定して日次同期を有効にします。[会社用環境への導入手順](company-pilot.md)も参照してください。

独自の列名の場合はCSV/TSVプレビューで対応を確認し、「確認済みプレビューの列対応を日次同期にも適用」を選んで接続設定へ保存します。日次設定には列名を保存するため、列順だけが変わった場合にも対応します。見出し自体が変わったときは再設定してください。

設定した日本時間（既定06:00）以降、最初のチェックで実行します。その時刻に停止していても、同日の設定時刻以降に起動すれば未実行分を取得します。チェック間隔は60秒。日次処理が当日すでに試行済みなら自動では再実行しません。手動同期は別に記録するため、手動更新後も当日の日次処理は実行します。失敗した日はエラーを確認して手動で再試行できます。停止中の複数日を遡ってスナップショットを作ることはできません。毎月自動切り替えは対象月の指定を変更し、取得するタブ名や範囲は変更しません。

同期はアカウントIDで新規作成・更新し、スプシから消えた行を勝手に削除しません。重複IDや不正金額がある場合は、全体を確定せず既存データを保持します。同期直前のマスタも履歴として保存します。

公式資料: [Sheets values.get](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get)、[サービスアカウント認証](https://developers.google.com/identity/protocols/oauth2/service-account)。

## Gemini要約の設定

Google AI Studioで利用できるGemini APIキーとモデルを確認し、サーバーの `.env` に設定します。

```dotenv
GEMINI_API_KEY=your-api-key
GEMINI_MODEL=gemini-3.1-flash-lite
GEMINI_AUTO_SUMMARY=true
```

キーはUI・フロントエンド配信ファイル・API応答には含めません。`VITE_` から始まる環境変数に置かないでください。設定後にサーバーを再起動し、「データ連携」に設定状態が表示されることを確認します。

保存時の自動実行設定がなくても、議事録画面の「要約を作成・再実行」で実行できます。Gemini設定時は原文・タイトル・商談日をGoogleのAPIへ送信します。要約やアクションの根拠は原文と照合され、原文にない根拠はエラーになります。ただし全ての解釈の正しさを保証する機能ではないため、タスク化前の人による確認を前提にしています。

Gemini未設定の場合は、ローカルで原文の先頭行と「決定」「課題」「次のアクション」などのキーワードを抽出します。これはAI生成ではなく、画面でも「ローカル要点抽出」と表示します。Geminiで失敗したときに、成功したように見せてローカルへ黙って切り替える処理は行いません。

要約待機・処理中の議事録はDBに状態を残し、サーバー再起動後に処理を再開します。タスク化後の要約再生成はアクション対応が変わるのを避けるため禁止し、新しい議事録として追記します。v2.3からGoogleドキュメントのURLによる本文取得と任意更新・改訂保存に対応しています。[設定方法](operations-and-integrations.md)を参照してください。PDF/DOCXの自動読取、音声の文字起こしは対象外です。

公式資料: [Gemini GenerateContent API](https://ai.google.dev/api/generate-content)、[構造化出力](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)、[モデル提供状況](https://ai.google.dev/gemini-api/docs/deprecations)。

## 運用・権限・検証の範囲

- 既存と同じ社内ログインが必要です。全メンバーが全営業アカウントを共有する仕様です。
- スプシの接続設定・同期・確定取込・サンプル追加は管理者だけが行えます。
- データは既存と同じSQLiteへ保存します。拡張前のDBバックアップを `data/backups` に作成しています。
- Google資格情報は `.secrets` に置く場合、GitとDockerビルド対象から除外されます。鍵はサーバー運用者だけが読める権限で管理します。
- Google SheetsとGeminiの通信はモックによる認証フロー・構造・エラー処理の検証まで実施しています。実スプシのURL・サービスアカウント・APIキーが未提供のため、実サービスへの接続確認は未実施です。
- 自動で担当者を評価するスコア、人事評価、需要の因果推論、複雑な会計予実、部署別アクセス権、複数台でのジョブ分散は実装していません。
