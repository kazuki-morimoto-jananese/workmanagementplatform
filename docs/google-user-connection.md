# Googleドキュメントの本人認証

GeminiのキーとGoogleドキュメントの閲覧権限は別です。GeminiはサーバーのAPIキーで動作します。Google文書は、接続先のアカウントが読める文書だけを取得します。

外部共有が禁止されている会社では、サービスアカウントへ共有する代わりに、利用者本人のGoogle OAuth認証を使います。会社のAPI利用制限を解除・迂回する機能ではありません。管理者がアプリの利用を許可する必要がある場合は、その許可が先に必要です。

## 管理者が一度だけ行うこと

1. プロジェクト直下の `connect-google.cmd` をダブルクリックします。Googleの設定画面と入力画面が開きます。
2. Google Auth Platformでアプリ名・連絡先・対象ユーザーを登録します。会社組織所有のプロジェクトなら「内部」を選びます。「外部・テスト」を使う場合は会社の利用者をテストユーザーに追加します。
3. OAuthクライアントを「ウェブアプリケーション」として作成し、スクリプトが表示するリダイレクトURIを完全一致で登録します。
4. クライアントJSONをダウンロードし、そのフルパスを入力画面へ貼り付けます。スクリプトがCloudflareの秘密設定へ登録します。JSONの内容をチャットやGitに載せないでください。
5. Google Docs APIを有効にします。既存のGoogleプロジェクトでは有効化済みか確認してください。

## 利用者が行うこと

Worknestの「営業・数字管理 → データ連携 → Googleアカウントに接続」で、Worknestのメールアドレスと同じGoogleアカウントを選び、文書の読み取りを許可します。

議事録登録でGoogleドキュメント読み取りを選び、URLを指定します。登録後は詳細の「Googleから更新」で再取得できます。変更時は新しい版として保存し、旧原文・要約・タスクとの対応を残します。コピーして登録した原文はGeminiで処理できますが、Google文書と自動的には結び付きません。URLから新たに読み込んで登録してください。

権限は `documents.readonly` と本人確認用の `openid email` です。Drive全体のファイル一覧を取得する権限や、文書を書き換える権限は要求しません。認証トークンはサーバーで暗号化して保存し、APIレスポンスには含めません。各利用者の本人認証は、その利用者による取得にだけ使用します。接続解除後はWorknestからその認証を使用できません。Google側の許可自体はGoogleアカウントの接続済みアプリから取り消せます。

「外部・テスト」のGoogle OAuth設定では、更新トークンが短期間で失効することがあります。長期運用では会社組織内のアプリ設定か、Googleが要求する公開・審査手続きが必要です。

参考：[GoogleのウェブアプリOAuth手順](https://developers.google.com/identity/protocols/oauth2/web-server)、[OAuthアプリと会社の利用制限](https://developers.google.com/identity/protocols/oauth2/production-readiness/overview)。
