# Google Sheetsを本人の権限で接続する

v2.9.1以降。Google Docs/Calendarと同じ本人OAuthへ、Sheetsの読み取り専用権限を追加します。外部サービスアカウントへの共有を不要にできますが、会社のAPI利用制限やWorknestへのデータ保存ルールを回避する機能ではありません。

## 利用者の操作

1. 管理者でログインし「営業・数字管理 → データ連携」を開きます。
2. 「スプシの接続方式」を「本人のGoogleアカウント」に変更します。スプシID・取得範囲を確認し、最初は日次同期を無効のまま「接続設定を保存」を押します。
3. 「スプシ閲覧を許可して接続」を押し、Worknestと同じメールアドレスのGoogleアカウントで閲覧を許可します。秘密キーの入力は不要です。
4. Worknestへ戻ったら同じデータ連携画面を開きます。「あなたの閲覧許可：取得済み」と、保存済みの接続方式・接続者を確認します。
5. 「保存済み接続をプレビュー」を押して件数・列・エラーを確認します。ここでは営業データは更新されません。
6. 問題がなければ「今すぐ同期」。日次更新も使う場合は同期時刻と「日次同期を有効にする」を設定して保存します。

取得範囲の例：`'プランニング_9/7'!A21:AP`。`A21:AP21` は21行目だけなので、見出ししか取得できません。タブ名に記号がある場合はシングルクォートで囲みます。月替わりでタブ名が変わる場合、対象月の自動切替とは別に取得範囲を変更してください。

## 接続者・データの扱い

- 初めて本人認証方式へ切り替えて保存した管理者が接続者になります。
- 他の管理者が時刻や範囲を編集しても、接続者は変わりません。変更するときは「本人認証の接続者を自分に変更する」を明示して保存します。
- 接続者の取得権限で、手動・日次とも同じ処理を実行します。取得する営業マスタはWorknest内で共有されます。接続者がWorknestからログアウトしていても、Googleの継続利用許可が有効なら同期できます。
- Google接続解除、接続者の停止・管理者権限の剥奪、Googleの認証失効時は同期に失敗し、エラーと履歴を残します。別の人やサービスアカウントへ自動で切り替えません。
- 既存の入力済みヨミ・商談・議事録はマスタ同期で上書きしません。0は有効な数値として扱います。
- Googleの読み取り権限は指定タブだけに限定されるものではありません。Worknestが取得する対象は保存したスプシID・取得範囲です。

## 失敗したとき

| 表示 | 確認すること |
| --- | --- |
| 閲覧許可がありません | 接続者本人が追加認証を実施したか。Google画面でSheetsの許可を外していないか |
| HTTP 403 | 接続者自身がスプシを開けるか、対象Google CloudプロジェクトでSheets APIが有効か、会社のAPI制限・利用上限。403だけで管理者の制限と断定しない |
| HTTP 404 | スプシID・閲覧権限・選んだGoogleアカウント |
| HTTP 400 | タブ名・取得範囲の書式 |
| 見出しだけでデータ行がありません | 取得範囲に2行目以降のデータを含める |
| Google認証が失効 | 接続者が再接続。Google OAuthアプリの公開状態によって継続認証の扱いが異なるため、本番設定も確認 |

初期設定担当はGoogle Cloudで **Google Sheets API（sheets.googleapis.com）** を有効にします。OAuthのリダイレクトURIは既存の `/api/google/callback` と共通です。今回追加した権限は `https://www.googleapis.com/auth/spreadsheets.readonly`。SSOログイン機能とは別です。

仕様の根拠：[Sheetsの取得API](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get)、[Google OAuthの追加認可・オフライン利用](https://developers.google.com/identity/protocols/oauth2/web-server)。
