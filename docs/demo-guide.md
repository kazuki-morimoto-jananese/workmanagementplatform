# 3か月の営業デモ

「営業・数字管理」の **表示データ → デモデータ** で、6つの架空アカウントを確認できます。未追加の環境では管理者が **3か月デモを追加** を押します。対象は追加時点の前月・当月・翌月です。既存の実データを保持し、再実行時は不足しているレコードだけを追加します。

2026年9月6日に生成した初期値の例です。金額はすべて円です。

| 対象月 | 月間目標 | 最新の担当者ヨミ | 目標との差 | スタンバイ消化実績 |
| --- | ---: | ---: | ---: | ---: |
| 前月：2026-08 | 29,700,000 | 29,331,000 | -369,000 | 29,331,000 |
| 当月：2026-09 | 33,000,000 | 31,972,000 | -1,028,000 | 6,420,000 |
| 翌月：2026-10 | 37,950,000 | 38,300,000 | +350,000 | 未発生 |

当月ヨミには、当週未更新の「リーフ採用支援」の前週値3,072,000円を引き継いでいます。入力率は5/6件です。アカウントの会議メモ内の見込みとヨミの更新時点が異なる場面も確認できます。

## 確認する流れ

1. **営業サマリー**で「前月」「当月」「翌月」を切り替え、目標・Gトレ・ヨミ・差額を比較します。
2. **週次ヨミ**でアカウントを開き、根拠、3媒体の予算・消化額・CPA・採用数を確認します。会議週を1週戻すと過去のヨミを確認できます。
3. **商談**で各月6件のフェーズ、金額、確度、次の行動を確認します。
4. **議事録**で各月6件の原文と要点を読み、「タスクを開く」から関連タスクへ移動します。
5. 左メニューの **デモ：営業アクション** プロジェクトで、タスクをリスト・ボード・タイムライン表示します。

前月のヨミは締め結果に一致します。当月は目標未達・達成見込み、Gトレ0円、CPA超過、顧客接点の停滞を含みます。翌月は計画・予算・見込みを表示し、未発生の消化額・CV・採用数は空欄です。月切り替え時は、その月のデモを確認できる会議週も設定します。

## 実データとの区別

- アカウント・プロジェクト・商談・議事録・タスクに「デモ」を表示します。
- 営業画面の集計、商談、議事録、履歴、CSVは「表示データ」で選択した種別に分かれます。実データのCSVへデモを混ぜません。
- タスク管理側ではデモ専用プロジェクトに追加します。既存のプロジェクトやタスクは変更しません。
- 担当者には既存の有効な社内メンバーを割り当てます。ログインアカウントは追加しません。
- 議事録の要点は架空原文から作るローカル抽出です。デモ生成によるGemini・Google Sheetsへの通信はありません。
- 数字は編集できます。「3か月デモを追加」を再度押しても編集内容は初期値へ戻しません。

## サーバーから追加する

初期管理者を登録した後、同じ処理をコマンドで実行できます。

```powershell
npm.cmd run backup
npm.cmd run demo:sales
```

Dockerでは `docker compose exec app node scripts/seed-sales-demo.mjs`。生成済みDBはGitに含めず、生成処理だけを共有します。新しい環境ではこの操作または画面のボタンで作成してください。
