# 取り込み照合・優先アクション・施策の成果追跡

v2.17 / 2026-09-16。既存の会社環境で利用できます。今回追加した処理にAI APIや外部サービスの認証は不要です。

## 1. 営業マスタの取り込み照合

「営業・数字管理 → データ連携 → Excel・CSV・貼り付け取込」で対象月・列対応を指定し、「取込内容を確認」を押します。

- 新規／変更あり／比較項目の変更なし、担当未紐付け、同名・別ID、停止中の件数を表示します。同名アカウントは自動統合しません。
- 前月実績・Gトレ・Excel今月ヨミ・アグレッシブについて、今回の取込対象IDだけの取込前・ファイル・取込後の合計と差を表示します。欠損を含む合計は既知値だけの部分集計です。
- 0円は数値、空欄は欠損として保持します。指定した列の空欄はマスタも空欄になります。「取り込まない」の列は既存値を保持します。入力済みの週次ヨミは従来どおり優先されます。
- 「この列対応を保存」は管理者が利用できます。同じ見出しと列順のファイルを新しく選んだ際に適用します。列名・列順が変わった場合は再確認してください。保存はワークスペース単位で30種類までです。
- プレビュー後に対象マスタ・担当者等が更新された場合は確定を停止します。もう一度「取込内容を確認」を押してください。Google日次同期の既存フローには、この手動確定用の確認待ちは追加していません。

この照合画面は営業マスタ用です。独立したアカウントマスタ・固定KGIサマリー・KW／配信面分析の取込画面は従来の検証を利用します。列対応のプリセットもそれぞれに自動適用されるものではありません。

## 2. 優先アクション

「営業・数字管理 → 優先アクション」。初期表示は自分の担当アカウントです。担当者と対応状況を切り替えられます。

候補は、期限超過タスク、担当者未紐付け、当週の手入力ヨミ未登録、14日超の接点、CPA上昇、Gトレ減少です。CPAは観測日が14日以内、Gトレは取得が3日以内のデータに限り判定します。CPAは前の週次記録から20%以上の上昇、Gトレは前週比20%超の減少を確認候補にします。金額が大きい候補を同じ重要度内で先に表示します。

配信停止等の状態では数値・接点・ヨミの確認を抑制します。Gトレ0円・欠損に対してヨミ入力を要求しません。CPAや予測の変化は要確認であり、成果悪化を断定するものではありません。タスクの表示には既存の閲覧権限を適用します。

「対応済み」「保留期限」「対応メモ」を保存できます。対応記録は対象月・会議週ごとに共有されます。根拠が変わる、保留期限が来る、または新しい会議週になると再確認対象になります。判定は画面上で行うため通知の自動送信はありません。

対応記録は5,000件まで。上限到達時に履歴を自動削除しません。

## 3. 施策・成果

1. 「商談準備・分析」でKWまたはLINEバイト・配信面の分析結果を共有保存します。
2. 「施策・成果 → 施策を登録」でアカウントを検索し、施策名・担当・提案内容・期待成果・実施日・検証予定日を入力します。
3. 実施前の分析と期間を選びます。新しいExcelで分析・保存した後に、実施後の分析・期間を選んで更新できます。同じ保存分析の期間A/Bも利用できます。
4. CV定義・期間・抽出条件・対象範囲を確認し、予算変更や季節性など他の変化と検証結果を記録します。
5. 必要に応じてプロジェクトを選び「施策をタスク化」。同じ施策からの重複作成を防ぎます。「変更履歴を表示」で更新前後を確認できます。

「提案中 → 合意済み → 実施中 → 検証済み」と中止を記録できます。実施中／検証済みには実施日が必要です。検証済みには前後の分析・比較条件の確認・検証結果も必要です。

前後の比較は同じ営業アカウント・分析種別／計算版・会社識別子に限ります。実施前の期間は実施日より前、実施後は実施日以降で、期間の重複は認めません。数値・出典は保存時点のスナップショットとして残ります。CVゼロと未計測、計算できないCPAを区別します。表示するのは分析対象全体の数値で、特定KWだけの効果を分離する機能ではありません。

前後差は因果効果ではありません。異なる期間日数、予算、配信範囲、抽出上限、CV定義を確認してください。画面の差分は合計値の単純差であり、日数補正や季節性の補正はしていません。

施策はワークスペース共有で月をまたいで表示し、1,000件まで保存できます。同時編集は版番号で保護し、変更履歴と全データ書き出しに含めます。検証の自動実行・AIによる因果判定は行いません。

## 4. DB読込と無料運用

- 同じリクエストや定期処理で繰り返す同一の読込を再利用します。利用者への返却値を別リクエストへ使い回しません。保存・削除・ロールバック・別処理の更新後は読み直します。
- 営業データの自動再読込は表示中60秒ごとに変更しました。画面の更新ボタンと保存直後の再読込は利用できます。
- 「データ連携 → DB使用状況」は管理者のみ。ボタンを押したときに、ストア読込回数・再利用回数・返却レコード件数、Cloudflareでは実際のSQLカーソルから観測した読込／書込行数と現在のDB容量を取得します。
- カウンターは稼働インスタンスのメモリ内です。再起動でリセットされます。SQL行数はUTC日付単位でリセットされ、起動前や他環境、SQL以外の使用量を含みません。ストアの返却件数は課金対象SQL行数ではありません。Cloudflare契約全体の無料枠残量は管理画面で確認してください。

有料プラン・AI API・常時の全件使用量集計は追加していません。ただし、アクセスや保存量の増加に対して無制限に無料利用を保証するものではありません。履歴は削除せず、既存の管理者向け全データ書き出しで保管できます。
