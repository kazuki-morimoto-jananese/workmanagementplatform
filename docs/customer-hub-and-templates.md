# 顧客カルテと商談準備テンプレート

v2.18。今回の追加機能は保存済みのWorknestデータを利用します。追加のGoogle認可・AI API・有料サービス契約は不要です。

## 顧客カルテ

「営業・数字管理 → 顧客カルテ」でアカウント名・IDを入力して選択します。初期表示は自分の担当アカウントです。「担当者」で他のメンバー・すべての担当者へ切り替えられます。担当者フィルターは閲覧権限ではありません。

- 当月Gトレ・最新週次ヨミ（週次入力がなければ取込ヨミ）、顧客の目標・課題、最終接点を確認できます。元データが未登録なら「—」「未登録」と表示します。
- 「カルテを編集」で法人名、ブランド、拠点、Webサイト、更新・契約確認日、引継ぎメモ、次に進めることを保存できます。確認日は記録用で、自動通知はありません。
- 関連アカウントを20件まで手動で追加できます。別ブランド・拠点等への参照リンクです。アカウントの統合、相互リンクの自動作成、数字の合算は行いません。
- 関係者を登録すると、その顧客のアカウントを設定した状態で既存の「顧客・リード」が開きます。部署・役職・顧客内の役割（決裁者／推進者／実務担当／購買・契約等）を記録できます。連絡許可は既存の項目を継続利用します。
- カルテ上の関係者は最終更新順で30件まで。すべての関係者の編集・フォロータスク作成は「顧客・リード」で行います。

カルテと関係者はワークスペース内で共有されます。同時編集で先の変更を上書きしないよう版番号で検査します。「カルテの変更履歴」から更新前後を確認できます。保存してから別の画面・顧客へ切り替えてください。

## 顧客のタイムライン

議事録、商談、活動、タスク、KW／LINE配信面の保存分析、施策、週次ヨミ、関係者を、対象アカウントごとに最終更新順で25件ずつ表示します。種類による絞り込みと「次の25件を表示」に対応しています。

一覧は短い抜粋のみ取得し、原文・分析の詳細は「詳細を開く」で取得します。タスクは既存の詳細画面を開きます。非公開タスクは作成者・担当者・管理者以外には表示せず、詳細取得時にも権限を検査します。改訂済み議事録の旧版はタイムラインから除外します。

これは**現在の記録を横断して見る一覧**で、すべての変更イベント・削除イベントを並べる監査ログではありません。更新前後は詳細の「この記録の変更履歴」、全社の履歴は管理者のデータ書き出しで確認できます。取得中に別の人が更新した場合は「タイムラインを更新」で読み直してください。

分析詳細には期間A/Bの合計、提案と根拠、ファイル名を表示します。ファイル全行やすべてのグラフを再表示する場合は既存の「商談準備・分析」で保存分析を開きます。

## 商談準備テンプレート

1. 「営業・数字管理 → 商談準備・分析」でアカウントを選びます。
2. 「今回の議題」の下の「商談準備テンプレート」から「初回商談」「運用定例・改善提案」、またはチームで作成したテンプレートを選びます。
3. 内容を確認して「議題・確認項目に追加して保存」。既存の議題の末尾に追記し、同じ版の二重追加を防ぎます。同名の確認項目は重複させず、既存のチェック状態・確認メモを保持します。
4. 商談準備で確認した項目をチェックし、結果をメモします。独自項目の追加・削除も可能です。
5. 「議題・チェックリストを保存」またはパネル下部の「確認内容を保存」で確定します。チェックの操作だけでは保存されません。

管理者は「チーム共通のテンプレートを管理」から共通テンプレートの作成、標準テンプレートのコピー、内容の編集、利用停止・再開ができます。組織名は分類用で、閲覧制限ではありません。一般メンバーはテンプレートを適用し、顧客ごとの議題・チェックリストを編集できます。

適用時のテンプレート名・版・議題・確認項目を顧客側へ保存します。後から共通テンプレートを編集・停止しても、適用済みの内容は変わりません。新しい版を適用すると追記されます。確認項目の自動タスク化や、チェックを強制する承認フローは今回の範囲外です。

保存上限は、共通テンプレート50件（利用停止を含む）、テンプレート内の確認項目20件、顧客ごとの確認項目30件・議題4,000文字・適用テンプレート10版です。上限超過時は保存を止め、既存内容を保持します。上限到達時に履歴を自動削除しません。

## 保存・無料運用

- 既存の永続SQLiteに保存し、カルテ・共通テンプレート・議題の変更を監査履歴と管理者向け全データ書き出しに含めます。
- 顧客ID・記録の種類・更新日時の専用インデックスを使用します。対象はタイムラインの8種類のみで、営業マスタの履歴等をインデックス対象に増やしません。
- 初回起動時に既存レコードからインデックスを作成します。これはSQLの読込・書込・保存容量を消費します。以降は対象レコードの更新時に維持します。
- 一覧は種類ごとに最大26件のメタデータを取得して25件のページにまとめます。取得件数と課金対象のSQL読込行数は同一ではありません。非公開レコードの除外等でも読込が発生します。
- 詳細・履歴は開いたときに取得します。新しい定期ジョブや常時の全件集計は追加していません。商談準備の保存分析一覧も顧客別インデックスを利用します。
- 「データ連携 → DB使用状況」で観測した使用量を確認できます。Cloudflare契約全体の残量はCloudflare管理画面で確認してください。

今回、有料プランへの変更・追加AI呼出し・新しい外部認証は行いません。利用量にかかわらず無料を保証するものではなく、既存の同期や履歴を含めて無料枠内で運用します。上限を超えた場合の制限は[Cloudflare公式仕様](https://developers.cloudflare.com/durable-objects/platform/pricing/)を参照してください。

実装範囲はWorknestのみです。別プロジェクトの商談準備Hubは変更していません。
