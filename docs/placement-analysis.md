# LINEバイト・配信面のExcel／CSV分析

「営業・数字管理 → 商談準備・分析」でアカウントを選択し、「分析するデータ」を「LINEバイト・配信面レポート（自社）」へ切り替える。

## 操作

1. Databricksからダウンロードした2期間のExcel（.xlsx）またはUTF-8 CSV／TSVを、期間A・Bにそれぞれ指定する。同じファイルに両期間がある場合は同じファイルを両方に指定できる。
2. シート・見出し行・列の対応を確認する。列順は固定しない。既知の見出しを推定し、異なる表記はプルダウンで指定する。
3. 日次／月次、比較期間、ファイル内のアカウント識別子を選ぶ。日付と識別子で対象行を絞り込む。月次は完全な暦月だけで比較し、月の途中への按分はしない。
4. アカウント・期間・円単位・CV定義・抽出条件を確認し「期間比較を実行」を押す。
5. 配信面別の構成・効率とキャンペーン別の内訳、元の配信面名と分類、使用／除外行数を確認する。
6. 提案文を編集し共有保存する。根拠付きタスク化、印刷画面からのPDF保存、分析結果JSONの出力を利用できる。保存済みのKW分析・配信面分析は同じ履歴から開ける。

分析種別を切り替えると未保存のファイル・分析はリセットされる。元ファイルを再分析する場合は再選択が必要。

## 対応列

商談準備Hubの `Config.gs`、`DeepDive.gs`、`Diagnosis.gs`、`pilot/databricks/meeting_prep_hub_newaccount_views.sql` を読み取り調査した。Hubのファイルは変更していない。

| 項目 | Hubの列名 | 必須・用途 |
| --- | --- | --- |
| 日付 | `period_date` | 必須。日次はYYYY-MM-DD／YYYY/MM/DD、月次はYYYY-MMまたは月初日。Excelの日付セルにも対応 |
| アカウント | `account_id` / `company_key` | 複数アカウントを含む場合に指定。省略すると全行を自社扱い |
| 配信面 | `publisher_category` | 列指定必須。空欄の値はUNKNOWN |
| 表示回数 | `impression` | 任意。IMP・CTRを算出するには必要 |
| クリック | `click` | 列指定必須 |
| 消化額 | `cost` | 列指定必須。円の実数 |
| CV | `cv` | 列指定必須。元データのCV定義を確認 |
| キャンペーンID・名 | `campaign_id` / `campaign_name` | 任意。提供されている場合に内訳を集計 |

`source_id`・`account_name`・`note`や、計算済みCPC／CPA等の追加列はそのままファイルに含められる。計算には対応づけた実数列だけを使う。

Hubの現行SQLは、キャンペーンに `PLACEMENT_TOTAL` / `Placement total` を出力する。この場合は全キャンペーン合算であり、個別キャンペーンの内訳を生成できたとは扱わない。`ALL_CAMPAIGNS` も同様。同じ日付・アカウントで全体合算と個別明細が混在すると、二重計上防止のためエラーにする。

## 計算と判断

- LINEは `LINE`・`LINEバイト`・`line baito` の完全一致（全半角・大文字小文字・空白を正規化）。`non-LINE`をLINEへ巻き込まない。
- 空欄・UNKNOWN・不明・未分類・null・ハイフン等はUNKNOWN。それ以外の提供値はnon-LINE。元の名称と分類例も表示し、未知の名称は利用者が確認する。
- 消化額／クリックからCPC、CV／クリックからCVR、消化額／CVからCPA、クリック／表示回数からCTRを計算する。行ごとの率を平均しない。
- 0は実数として保持する。空欄は欠損、0の分母は率不明。欠損を含む関連合計は不明となる。
- 構成比の分母はファイル内の対象アカウント・対象期間の全配信面。UNKNOWNも含む。LINEのみを抽出したファイルで事業全体の構成比は算定できない。
- 同じ日付・アカウント・キャンペーン・元配信面の重複行は、数値が違っていても拒否する。
- 自社消化額に対する重要度、CPA変化、CVゼロ、消化構成変化等から施策候補を作る。LINE構成比の10ポイント以上の上昇時には、non-LINEとのCPA差も合わせて確認対象とする。構成変化を効率悪化の原因とは断定しない。

## 範囲と制限

自社の配信面分析に対応する。競合配信面の実データはHubの運用資料でも未提供とされているため、競合配信面比較を完成済みとは扱わない。

ファイルは各5MB・1万行まで、Excelブックは50万セルまで。配信面別合計は対象全行を集計し、キャンペーン×配信面の詳細は消化額順80件、元の配信面名の分類例は30種類、施策候補は30件まで保存する。

保存上限はKW分析と共有し、結果1件120KB・全体500件または40MB。保存済み結果・根拠・タスクは既存の監査／バックアップ対象。原本や全明細は保存しない。サーバーは形式・保存上限を検証し、`browser-calculated`として保存する。独立したサーバー再計算ではない。

数値計算はブラウザーのWorkerで実行するため、Databricks API・追加Google権限・Gemini／Claudeの呼び出しは不要。提案文はルールに基づく候補として作り、担当者が編集する。Cloudflare無料枠はログイン・履歴保存などに引き続き適用される。超過時の挙動は[公式のDurable Objects料金仕様](https://developers.cloudflare.com/durable-objects/platform/pricing/)を参照。

将来のAPIは、ファイル正規化と同じ `PlacementRow`（日付・アカウント・配信面・キャンペーン・実数）へ変換して分析へ渡せる。今回Databricksの自動接続やGoogle Slides／PPTX出力は追加していない。
